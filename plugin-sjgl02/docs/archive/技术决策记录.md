## ADR-001: 使用 ioredis-mock 替代外部 Redis

**日期**: 2026-07-15  
**状态**: ✅ 已采纳

**背景**: 用户无法配置外部 Redis，需要插件自带 Redis 解决方案

**决策**: 使用 ioredis-mock 作为内存模拟

**后果**:
- ✅ 优点: 无需外部依赖，开箱即用，适合单机部署
- ⚠️ 限制: 数据不持久化，服务重启后队列丢失
- ⚠️ 限制: 不支持多实例部署

**实现**: 
- Bull Queue 使用 ioredis-mock 作为 Redis 客户端
- 服务启动时检查 `sjgl02Tasks` 表，将 `running` 状态的任务标记为 `failed`

## ADR-002: WorkbookReader V2 流式读取

**日期**: 2026-07-15  
**状态**: ✅ 已采纳

**背景**: 100 万行导入需要控制内存使用

**决策**: 使用 `ExcelJS.stream.xlsx.WorkbookReader` 流式读取

**验证结果**:
- 50 万行内存峰值: 649 MB（V1 为 1,671 MB）
- 降幅: 61%
- 100 万行预估内存: 1.3 GB（在 1.5 GB 预算内可用）

**后果**:
- ✅ 内存可控，适合大规模数据
- ⚠️ 代码复杂度提高（需要手动处理流）

## ADR-003: 严格模式单大事务

**日期**: 2026-07-15  
**状态**: ✅ 已采纳

**背景**: 保证数据一致性，任何错误都不应部分写入

**决策**: 所有导入操作在一个事务中执行，失败全部回滚

**后果**:
- ✅ 数据一致性 100%
- ⚠️ 导入期间锁表（100 万行约 2 分钟）
- ⚠️ 任何一行失败，全部重新导入

**实现**:
- 导入前预检（唯一值不能为空）
- 批量写入但在同一事务内
- Commit 一次性提交，Rollback 快速回滚（<20ms）

**UI 提示**: 导入开始前提示用户"导入期间该表将被锁定"

## ADR-005: 系统字段 Excel 映射优先

**日期**: 2026-07-15  
**状态**: ✅ 已采纳

**背景**: 
- 日常导入新订单：系统自动填充 createdAt/createdBy
- 数据迁移：需要保留 Excel 中的历史时间和创建人

**决策**: Excel 映射优先

**实现逻辑**:
```typescript
if (fieldMapping.includes('createdAt')) {
  // 用户映射了 → 使用 Excel 值
  record.createdAt = parseDate(excelRow.createdAt);
} else {
  // 未映射 → 系统自动
  record.createdAt = new Date();
}
```

**使用方式**:
- 日常导入：不映射系统字段 → 系统自动
- 数据迁移：映射系统字段 → 使用 Excel 值

## ADR-006: 关联字段仅支持主键值

**日期**: 2026-07-15  
**状态**: ✅ 已采纳

**背景**: 关联字段可以填主键 ID 或显示值（如客户名称）

**决策**: 仅支持填主键 ID，不支持显示值智能匹配

**理由**:
- 简化实现，避免复杂的查询逻辑
- 主键值匹配更精确，避免重名问题
- 性能更好（直接关联，无需额外查询）

**后果**:
- ✅ 实现简单，性能好
- ⚠️ Excel 准备工作更复杂（需要填 ID 而非名称）

## ADR-011: 附件上传异步处理

**日期**: 2026-07-15  
**状态**: ✅ 已采纳

**背景**: 20 万个附件上传耗时过长（并发 10 需要 17 分钟）

**决策**: 数据先导入，附件后台异步处理

2. 创建独立的附件处理任务（后台运行）
3. 用户看到主任务"已完成"，附件任务"处理中"

**性能参数**:
- 并发数: 30
- 预估时间: 20 万附件约 5.5 分钟

**任务状态**:
```typescript
{
  mainTask: {
    taskId: 'task-001',
    type: 'import',
    status: 'completed', // 数据导入完成
  },
  attachmentTask: {
    taskId: 'task-001-attachment',
    type: 'attachment-processing',
    status: 'running', // 附件处理中
    parentTaskId: 'task-001',
  }
}
```

## ADR-024: 导出字段受权限配置控制

**日期**: 2026-07-15  
**状态**: ✅ 已采纳

**决策**: 导出功能的字段选择也受权限配置的白名单约束

**实现**:
```typescript
// 步骤②选择字段时
const exportableFields = collection.fields.filter(f => {
```

## ADR-026: 导入功能无"全部数据表"选项

**日期**: 2026-07-15  
**状态**: ✅ 已采纳

**背景**: 区分导入和导出的权限控制策略

**决策**: 
- **导入功能**：所有用户（包括 Admin/Root）都受权限配置约束
- **导出功能**：Admin/Root 有"全部数据表（含系统表）"特殊选项

**理由**:
- 导入影响数据完整性，需要严格权限控制
- 导出仅读取数据，Admin/Root 可以有更大权限

**实现**:
```typescript
// 导入步骤①
const collections = await getCollectionsWithImportPermission(userId);
// 无论是否 Admin，都受权限约束

// 导出步骤①
if (isAdmin(userId)) {
  collections = [specialOption, ...await getAllCollections()];
} else {
  collections = await getCollectionsWithExportPermission(userId);
}
```

## ADR-027: 关联字段导出增加"显示值+主键值"选项

**日期**: 2026-07-15  
**状态**: ✅ 已采纳

**背景**: 导出关联字段时，用户可能需要同时看到名称和 ID

**决策**: 关联字段处理提供 3 个选项
1. 显示值（如 "XX公司"）
2. 主键值（如 "123"）
3. **显示值+主键值**（如 "XX公司(123)"）← 新增

**输出格式**:
```
客户列：XX公司(123)
产品列：产品A(1), 产品B(2), 产品C(3)
```

**实现**:
```typescript
if (exportFormat === 'display+id') {
  return `${record.displayField}(${record.id})`;
}
```

**后果**:
- ✅ 灵活性提升
- ✅ 适合需要重新导入的场景
- ⚠️ Excel 列内容更长

## ADR-028: 权限管理改为两栏布局

```
└────────┴──┴──────┘────────┘
```

**后果**:
