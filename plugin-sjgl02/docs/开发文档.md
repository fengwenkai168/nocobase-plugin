## 1. 产品概述

### 1.1 定位

企业级数据管理插件，为 NocoBase 提供**大规模 Excel 数据导入/导出、异步任务管理、表级权限控制**三大能力，核心解决：

- 业务人员自助完成大批量数据导入（xlsx/xls/csv），无需开发介入；
- 业务人员按需导出数据（含关联表、附件），格式可直接用于再次导入或外部分析；
- 管理员对用户/角色按"数据表 × 操作 × 模式 × 字段"维度做细粒度管控；
- 所有导入导出异步执行，进度可追踪、可取消、严格事务保证数据一致性。

### 1.2 四大功能模块

| 模块 | 说明 | 设置页入口 | 页面区块入口 |
|---|---|---|---|
| ⬇ 导入 | 3 步向导：选表传文件 → 配置映射 → 预览执行 | ✅ | ✅ |
| ⬆ 导出 | 3 步向导：选表 → 选字段配置 → 执行导出 | ✅ | ✅ |
| ☰ 任务管理 | 任务列表、进度追踪、详情抽屉、取消、下载 | ✅ | ✅ |
| ✓ 权限管理 | 用户/角色表级权限 CRUD、操作日志 | ✅ | ❌（仅设置页） |

### 1.3 两个入口（信息架构）

1. **插件设置页**（完整功能）：`插件设置 → 数据管理 sjgl02`，内含「导入 / 导出 / 任务管理 / 权限管理」4 个 Tab。前端路由使用 `/v/` 前缀。
2. **v2 页面区块**（操作功能）：页面编辑器 → 添加区块 → 其他区块 → **数据管理02-sjgl02**，内含「导入 / 导出 / 任务管理」3 个 Tab（无权限管理）。

两个入口复用同一套 React 组件，通过 props（如 `showPermissionTab`）控制差异。

### 1.4 非目标（本期不做）

- 不支持子表格/子表单字段的导入（直接忽略，不报错）；
- 关联字段导入仅支持主键值，不做"显示值"智能匹配；
- 不支持任务删除（任务永久保留，后续版本再考虑归档）；
- 不支持定时导入、API 推送导入、增量同步；
- 多实例部署（任务队列为进程内实现，单机场景）。

## 2. 已确认技术决策（ADR 摘要）

> 完整 28 条历史 ADR 见 `docs/archive/技术决策记录.md`。以下为现行有效决策，含本次重写时对冲突点的**最终裁决**。

### 2.1 数据规模与性能（spike 已实测验证，PG 16）

| 决策 | 结论 |
|---|---|
| Excel 读取 | **禁用全量加载**（`workbook.xlsx.read`，50 万行峰值 1671MB 会 OOM）；必须用 `Excel.stream.xlsx.WorkbookReader` 逐行异步迭代（50 万行峰值 649MB，2GB 服务器可行） |
| 导入事务 | **严格模式单大事务**：任何行失败或任务取消 → 整批 rollback（PG 实测 50 万行 rollback 仅 9ms）。UI 必须明确提示"失败全部回滚" |
| 导出写入 | 游标分页查询 + `stream.xlsx.WorkbookWriter` 流式写入（100 万行导出 39.5s，内存增长仅 58MB），**导出不设行数上限** |
| 文件下载 | 一律 `ctx.body = fs.createReadStream(path)`，禁止 `readFileSync`（27MB 文件实测 289MB vs 247MB 峰值，大文件必 OOM） |

### 2.2 行数上限（本次裁决）

- **导入**：`.xlsx` ≤ 50 万行、`.xls` ≤ 20 万行、`.csv` ≤ 50 万行（**以原型 UI 文案为准**，覆盖旧 ADR-004 的 100 万说法）。
- **导出**：无上限；单 xlsx 文件超过 100 万行自动分表（每 100 万行一个新文件，默认开启无需设置）。

### 2.3 任务队列（最终定稿，无降级方案）

**方案：DB 任务表（`sjgl02Tasks` 持久化）+ `app.eventQueue` 进程内调度 + AbortController 取消。零新增队列依赖。**

- 裁决理由：
  - 需求本质是"串行异步执行 + 取消 + 进度落库"，不需要 Redis 的延迟队列/优先级等高级语义；
  - `ioredis-mock` 是单元测试模拟库，部分 Redis 命令/LUA 脚本不支持，**带入生产有运行时风险**，一次性否掉；
  - `app.eventQueue`（`MemoryEventQueueAdapter`）为 NocoBase 内核自带，`plugin-async-task-manager` 在生产环境验证使用，装上插件即用，生产环境零外部服务要求。
- 执行设计：
  1. 提交任务 → 写 `sjgl02Tasks`（pending）→ `app.eventQueue.publish('sjgl02:task', { id })`；
  2. 订阅者串行消费（并发 1，避免大事务互相锁表），进度写库供前端 2s 轮询；
  3. 取消 → AbortController 中断 → 事务 rollback → 状态 `canceled`；
  4. 启动恢复 → **应用启动完成后**（`afterStart`/`afterSync` 钩子，`load()` 阶段 DB 未 sync 严禁查库）将残留 `pending/running` 任务标记为 `failed`（message="服务重启中断"）。
- 依赖：`package.json` 不引入 bull / ioredis-mock（已移除）；仅需 `exceljs`（仓库已装 4.4.0）与 `tar-stream@^3.1.6`（yarn install 同步）。

### 2.4 导入业务规则

| 决策 | 结论 |
|---|---|
| 导入模式 | `insert`（新增）/ `update`（更新）/ `upsert`（新增+更新），本次可用模式由所选权限配置决定 |
| 系统字段（createdAt/updatedAt/createdById/updatedById） | **Excel 映射优先**：映射了用 Excel 值；未映射系统自动填充（详见 4.1.8 规则表） |
| 主键 | 动态发现（不写死 id）：自增型未映射自动生成；自动生成型（uuid/nanoid/snowflakeId）由 hook 生成；手动型（string）必须映射且非空。主键值与库内或本批次重复 → 整批回滚 |
| 关联字段 | 仅按**目标表主键值**关联（动态获取 PK，不写死 id）；m2o 单值，o2m/m2m 逗号分隔多值**全量替换** |
| 唯一值字段 | 用于匹配已有记录（组合匹配，全部相等才算同一条），最多 3 个；update/upsert 模式必选至少 1 个；权限已配置 → 预填锁定不可改，未配置 → 自由选择 |
| 空值唯一值预检 | update/upsert 模式下导入前预检所有行唯一值字段，任一为空 → **整批回滚**（不开始导入） |
| 空白字段处理 | 两种策略：「按Excel更新（清空）」（默认）/「不更新（保留原值）」，仅影响 update/upsert |
| 多对多空值策略 | update/upsert 下 Excel 中关联字段为空时：「清空关联」（默认）/「保留原关联」；Excel 有值时始终全量替换 |
| 权限约束 | **导入对所有用户（含 Admin/Root）都受权限配置约束**（ADR-026），无权限的表在步骤①直接不显示 |
| Admin/Root 模拟权限 | Admin/Root 导入时可选择任意用户/角色的权限配置执行；选用户权限时数据 createdBy=该用户，选角色权限时 createdBy=Admin；任务 createdBy 恒为实际操作人 |

### 2.5 附件规则

| 决策 | 结论 |
|---|---|
| 导入附件包 | `tar.gz`，目录结构 **`attachments/<字段标识>/<文件名>`**（按字段分目录，避免多附件字段同名文件冲突；覆盖原型"全部放 attachments/ 根目录"的文案） |
| Excel 附件列 | 填文件名（含扩展名），多附件逗号分隔（如 `photo1.jpg, doc.pdf`） |
| 附件开关关闭 | 忽略 Excel 中的附件列，不报错 |
| 匹配失败 | 严格模式：找不到文件/未传压缩包但 Excel 有值/文件类型不允许 → 该行失败 → 整批回滚 |
| 附件处理 | 数据导入完成后异步执行附件子任务（并发 30） |
| 导出附件 | 打包为 tar.gz 随导出文件一并下载 |

### 2.6 导出规则

| 决策 | 结论 |
|---|---|
| 导出格式 | 固定 xlsx；「全部数据表」模式每表一个独立 xlsx，打包 tar.gz |
| 全部数据表（含系统表） | **仅 admin/root 可见可用**；每张表导出全部字段为独立 xlsx，无需逐表配置字段/关联 |
| 关联字段导出值 | 三选项：显示值（关联表显示字段）/ 主键值（动态 PK）/ 显示值+主键值（如 `管理员(1)`） |
| 关联表导出 | 用户勾选需要导出的关联字段，每个关联表作为**单独 Sheet** 或**单独 xlsx 文件**；Sheet 命名：`主表字段名称(主表字段标识)-关联表名称(关联表标识)`；多对多关联表 Sheet 含中间表映射数据 |
| 权限约束 | 导出字段同样受权限白名单（exportFields）约束；权限配置的 exportFilter（导出范围筛选）由**后端强制合并**进查询条件，用户不可绕开 |
| 文件命名 | 单表：`数据表名称-数据表标识-年月日时分秒.xlsx`；全部表：`全部数据表-年月日时分秒.tar.gz` |
| 字段显示格式 | 全系统统一 **「字段标题(字段名)」**，如 `地址(address)` |

### 2.7 权限模型决策

| 决策 | 结论 |
|---|---|
| admin/root | 自动拥有全部权限（所有表导入导出、全部模式、全部字段、含系统表导出、任务查看全部、权限管理），无需配置、不可修改、不可删除 |
| 权限不合并 | 用户自定义权限与各角色权限**互相独立、不合并**；导入/导出时用户**手动选择一套**权限配置执行（下拉只列出"本表有配置的"权限） |
| 用户权限组成 | 用户视角 = 用户自定义权限（可编辑）+ 角色继承权限（只读展示，按角色分组） |
| 任务查看范围 | 按用户维度配置：「仅查看自己的」（默认）/「查看全部」；无 `sjgl02.tasks` 权限者自动按 createdById 过滤 |
| 权限操作日志 | 权限配置的增/删/改/开关切换自动写日志（hook），含操作前后快照 |

### 2.8 工程规范

- 客户端 **只用 client-v2（FlowEngine/FlowModel）**，禁止 client v1（SchemaComponent）、禁止 Provider 滥用、组件必须懒加载；
- Collection 一律 `defineCollection()` + `export default`；主键统一 `bigInt autoIncrement`；
- 服务端状态值统一：`pending / running / succeeded / failed / canceled`（原型 UI 的"排队中/进行中/已完成/失败/已取消"为显示文案）；
- 权限日志 action 值：`create / update / delete / toggle`；
- 单文件 ≤ 500 行；i18n 从插件 `locale.ts` 导出 `tExpr`/`useT`，用户可见文案全部走 i18n（zh-CN + en-US）。

## 3. 数据模型（3 张自建表）

主键均为 `id: bigInt autoIncrement`。

### 3.1 sjgl02Tasks（导入/导出任务表）

| 字段 | 类型 | 说明 |
|---|---|---|
| type | string | `import` / `export` |
| status | string | `pending` / `running` / `succeeded` / `failed` / `canceled` |
| title | string | 任务标题（如"用户（users) 导入"） |
| collectionName / collectionTitle | string | 目标表标识 / 标题（全部表导出时记特殊值 `__all__`） |
| params | jsonb | 任务配置全量快照（导入：fileName/sheetName/headerRow/mode/uniqueFields/blankStrategy/m2mStrategy/mapping/attachment；导出：fields/dateFormats/relationConfig/headerType/filter/exportAttachment/allTables 等） |
| result | jsonb | 完成时结果快照（含错误明细前 100 条、预览行前 10 行） |
| progressTotal / progressCurrent | integer | 进度 |
| totalRows / successRows / errorRows | integer | 冗余统计列 |
| filePath / fileName / fileSize | string / integer | 导入=源文件；导出=结果文件 |
| errorReportPath | string | 错误报告文件路径 |
| permissionConfigId / permissionType | integer / string | 执行时使用的权限配置快照引用 |
| message | text | 失败原因等说明 |
| startedAt / doneAt / duration | date / integer | 执行时间与耗时（秒） |
| createdById | belongsTo users | 创建人 |

配置：`createdBy: true, updatedBy: false, logging: true`。

### 3.2 sjgl02Permissions（表级权限配置表）

| 字段 | 类型 | 说明 |
|---|---|---|
| targetType | string | `user` / `role` |
| targetId | string | 多态外键：userId 或 roleName（字符串形式） |
| targetName | string | 显示名冗余（角色取 `roles.title`） |
| collectionName / collectionTitle | string | 数据表标识 / 标题 |
| canImport / canExport | boolean | 导入/导出开关 |
| importModes | jsonb | 允许的导入模式数组，如 `["insert","upsert"]` |
| uniqueFields | jsonb | 唯一值字段（配置即锁定；空=导入时自由选择） |
| requiredFields | jsonb | 必填字段 |
| importFields | jsonb | 可导入字段白名单（**空=全部允许**） |
| exportFields | jsonb | 可导出字段白名单（**空=全部允许**） |
| exportFilter | jsonb | 导出范围筛选条件（后端强制执行） |
| sort | integer | 排序 |

唯一约束：`(targetType, targetId, collectionName)`。

### 3.3 sjgl02PermissionLogs（权限操作日志表）

| 字段 | 类型 | 说明 |
|---|---|---|
| action | string | `create` / `update` / `delete` / `toggle` |
| targetType / targetId / targetName | string | 操作目标 |
| collectionName / collectionTitle | string | 数据表 |
| permissionId | integer | 关联权限配置 id |
| beforeValue / afterValue | jsonb | 操作前/后快照 |
| summary | string | 变更概要（如"修改权限：导入模式+唯一值字段变更"） |

`logging: false`（避免递归）；由权限 CRUD 的 hook 自动写入。

**任务查看范围**（仅自己/全部）：为用户维度配置，存入 `sjgl02Permissions` 之外的用户偏好——使用 NocoBase 用户扩展字段或插件内 KV（建议：`sjgl02Tasks` 集合外加一条 `targetType=user, collectionName='__scope__'` 的偏好记录，或存入用户 metadata，实现时二选一并在代码注释说明）。

## 4. 功能需求详述

> UI 布局、文案、交互细节**一律以 `docs/sjgl02-prototype.html` 为准**，本章只定义业务逻辑与规则。

### 4.1 导入（3 步向导）

#### 4.1.1 步骤一：选择数据表 & 上传文件

- 数据表下拉：**仅显示当前用户拥有导入权限（canImport=true）的表**；显示"共 N 张表可供选择"。
- 上传：点击/拖拽；支持 `.xlsx`（≤50万行）/ `.xls`（≤20万行）/ `.csv`（≤50万行）；超限在服务端预检时直接报错。
- 表+文件都就绪才可"下一步"。

#### 4.1.2 步骤二：配置映射

页面信息栏固定显示目标表与上传文件。

1. **Sheet & 表头设置**：Sheet 下拉（上传后由后端解析返回 sheet 列表）、表头行行号（1/2/3）、「刷新」「预览前10行」（弹窗实时读取文件）。
2. **权限切换**：下拉列出"本表有配置的"权限（分组：👤 用户权限 / 🔐 角色权限；普通用户仅自己的用户权限+所属角色权限；admin/root 可见全部）。选中后展示**权限详情摘要卡片**（类型/导入模式/唯一值/必填字段/可导入字段）。
3. **导入模式**：由权限的 `importModes` 决定——仅 1 个模式 → 只读锁定；多个 → 可下拉切换。
4. **空白字段处理**：单选「按Excel更新（清空）」（默认）/「不更新（保留原值）」。
5. **多对多空值策略**：仅 update/upsert 显示；单选「清空关联」（默认）/「保留原关联」。
6. **唯一值字段**：仅 update/upsert 显示；chips 多选最多 3 个；权限已配置 → 预填+锁定（隐藏添加/删除）；未配置 → 自由选择（至少 1 个）。下方固定显示空值预检警告（update/upsert 时）。
7. **字段映射**：表格行为"数据表字段"，列为"Excel 列来源"。每字段三选一：
   - **Excel 列**：下拉选列，每列只能被一个字段占用（已占用置灰并提示被谁占用；强选产生冲突标红）；
   - **自定义内容**：输入固定值，整列同值；
   - **忽略**（默认）。
   支持「清空匹配」「自动匹配」（跳过系统字段）。列头计数"(共N列/已用X/剩余Y)"。字段行仅显示权限 `importFields` 白名单内字段（空=全部）。属性标签：主键/唯一值/必填/系统字段；系统字段被映射 Excel 列时行高亮 + "⬆ Excel优先"标签。
8. **附件导入**：开关默认关（"不需要附件"）；开启后上传 `attachments.tar.gz`（结构见 2.5），提供预制模板下载（含示例 Excel + 空目录）。
9. **NocoBase 系统字段处理逻辑**：折叠面板，展示规则表（见 4.1.8），纯说明不参与配置。
10. **脏数据保护**：步骤二任何修改后，切换 Tab/步骤/关闭页面弹"当前配置未保存"确认。

#### 4.1.3 步骤三：预览 & 执行

- 确认卡片：预计导入行数、错误行数（预检）、导入文件/数据表/Sheet/表头行/导入模式/唯一值/附件/空白值处理/事务模式（严格模式）/空值唯一值预检状态。
- 预览表（前 10 行）：表头换行显示"导入： Excel列 ▼ 数据表： 字段标题（字段名） - 类型"+属性标签；自定义内容列绿色显示。
- 「执行导入」→ 确认弹窗（含行数、模式、回滚警告）→ 创建任务（防重复提交：提交中按钮禁用）→ toast 提示去任务管理查看 → 重置回步骤一。

#### 4.1.8 系统字段与字段类型处理规则（导入引擎核心规则表）

| 字段类型 | 新增 | 更新 | 处理逻辑与失败粒度 |
|---|---|---|---|
| createdAt | 忽略（Excel映射优先） | 保留原值（Excel映射优先） | 未映射：新建自动填当前时间/更新不改；映射非空但无法解析日期 → 该行失败 |
| updatedAt | 忽略（Excel映射优先） | 忽略（Excel映射优先） | 未映射：始终自动填当前操作时间；映射非法日期 → 该行失败 |
| createdById | 忽略（Excel映射优先） | 保留原值（Excel映射优先） | 未映射：新建填当前操作人（Admin/Root 模拟用户权限时=该用户）；映射的用户不存在 → 该行失败 |
| updatedById | 忽略（Excel映射优先） | 忽略（Excel映射优先） | 未映射：始终填当前操作人；映射的用户不存在 → 该行失败 |
| 主键 | 可选 | 可更新 | 动态发现；手动型必须映射非空；与库内/批次内重复 → **整批回滚** |
| 单行/多行文本 | 直接写入 | 直接覆盖 | 必填+Excel空+空白策略=清空 → 该行失败 |
| 整数/数字 | 类型转换 | 类型转换 | 转换失败（如"abc"）→ 该行失败 |
| 单选/多选 | 标签匹配 | 标签匹配 | Excel 填选项**显示名称**，多选逗号分隔；选项不存在 → 该行失败 |
| 布尔 | 智能转换 | 智能转换 | 认 true/false、是/否、1/0、启用/停用；无法识别 → 该行失败 |
| 日期时间 | 格式解析 | 格式解析 | 支持：`YYYY-MM-DD HH:mm:ss`、`YYYY/MM/DD HH:mm:ss`、仅日期（时间补零）、ISO 8601、毫秒/秒时间戳（自动判断）、Excel 序列号；全不认 → 该行失败 |
| 多对一（m2o) | 按目标表主键关联 | 按目标表主键更新 | 主键值不存在或类型不匹配 → 该行失败 |
| 一对多/多对多 | 全量替换 | 全量替换 | 逗号分隔主键值批量关联；任一不存在 → 该行失败；Excel 空时按多对多空值策略 |
| 附件 | 从 tar.gz 上传 | 从 tar.gz 上传 | 找不到文件/未传包但有值/类型不允许 → 该行失败 |
| 子表格/子表单 | 忽略 | 忽略 | 跳过，不报错 |
| 公式/计算 | 忽略 | 忽略 | 导入后由系统重新计算 |

**失败粒度总结**：
- **该行失败**：单行业务校验失败（类型/选项/关联/必填等）→ 累计错误行；**严格模式下任何 1 行失败即整批回滚**（错误明细记入任务 result，前 100 条 + 可下载错误报告）。
- **整批回滚**（预检阶段直接终止）：主键未映射/为空/重复、唯一值为空、行数超限、文件解析失败。

### 4.2 导出（3 步向导）

#### 4.2.1 步骤一：选择数据表

- 下拉列出有导出权限的表；**admin/root 额外可见「📦 全部数据表（含系统表）」**置顶选项。

#### 4.2.2 步骤二：选择字段 & 配置

- **全部数据表模式**：隐藏单表配置区，仅配置全局项：日期时间导出格式（5 选 1）、关联值导出格式（3 选 1）。每表导出全部字段。
- **单表模式**：
  1. **权限切换**：同导入逻辑；可导出字段自动锁定为权限 `exportFields`（空=全部），白名单外字段置灰不可勾选。
  2. **字段选择**（仅显示有权限字段，支持全选/计数）：分四组——常规字段、日期时间字段（勾选后可逐字段配置导出格式，候选格式带预览）、关联字段（显示 `字段标题(字段名) - 类型 -> 关联表 显示字段`，多对多附中间表/外键信息；勾选后可配置导出值三选项）、附件字段。
  3. **关联表导出模式**：开关默认关；开启后多选关联字段 chips，导出方式单选「单独 Sheet」（默认，命名见 2.6）/「单独 xlsx 文件」（多文件打包 tar.gz）。
  4. **表头格式**：单选「字段名称（字段名）」（默认）/「字段名称」/「字段名」。
  5. **数据范围**：「全部数据」（默认）/「自定义条件」（AND 条件组：字段+操作符+值，可增删行）。**后端强制执行权限 exportFilter 与自定义条件的 AND 合并**。
  6. **高级选项**：导出附件开关（打包 tar.gz）；提示百万行自动分表；格式固定 xlsx。
  7. 脏数据保护同导入。

#### 4.2.3 步骤三：执行导出

- 单表：确认卡片（选择字段数/预计导出行数/数据表/数据范围/表头格式/关联表导出/附件/分表/格式）+ 选中字段标签墙 + 文件名预览。
- 全部表：确认卡片（表数量/总行数/范围/打包格式/附件/格式）+ 导出表清单（含中间表、系统表标识）。
- 「执行导出」→ 确认弹窗 → 创建任务（防重复提交）→ toast → 重置。

### 4.3 任务管理

- **统计概览**：6 张卡片（总数/已完成/进行中/排队中/失败/已取消），点击卡片快捷过滤。
- **筛选栏**：类型（全部/导入/导出）、状态（全部/排队/进行/完成/失败/已取消）、搜索（表名/任务ID/创建人）。

- **详情抽屉**（右侧 1024px）：
  - KPI 卡片网格：类型/状态/目标表/进度/创建人/创建时间/完成时间/耗时/数据量；
  - 任务配置详情（斑马纹）：任务ID/文件名/大小/Sheet/表头行/导入模式/唯一值/空白值处理/附件/权限配置/事务模式；

  - 导出任务：导出字段、导出配置、关联表导出详情表、导出数据预览（前 10 行）；
  - 下载区（已完成）：导出文件下载；导入任务可下载**源文件**；
  - 全部日志：成功/失败占比条；失败明细表（行号/字段/错误原因/原始数据，搜索+加载更多，每页 10 条）+「导出错误报告（CSV）」；

- **进度刷新**：打开进行中任务抽屉时前端每 2s 轮询任务详情，完成/失败/取消后停止。

### 4.4 权限管理（仅设置页入口）

- **左侧栏**：用户/角色列表（分组显示、搜索）；用户项显示其角色摘要。

- **权限配置区**：
  - 角色继承权限（仅用户目标显示）：按角色分组折叠，**只读**，仅可"查看详情"弹窗；继承自 admin/root 时显示全部权限提示；
  - 自定义权限：卡片列表（表名 + 权限标签行：导入/导出/模式/唯一值/必填/可导入/可导出/筛选），支持全选、搜索过滤、编辑、删除（二次确认）。
- **权限编辑弹窗**：
  - 选择数据表（必填）；
  - 「允许导入」「允许导出」两个独立开关，各自展开配置区；
  - 导入配置：导入模式（chips 多选，必选≥1）、唯一值字段（含 update/upsert 时必选，模式 chips 变化联动显隐该行）、必填字段、可导入字段（chips，空=全部允许）；
  - 导出配置：可导出字段（chips，空=全部允许）、导出范围筛选（可选，条件行增删）；
  - 保存后写权限操作日志。
- **操作日志**：表格（时间/操作人/操作类型标签/目标/数据表/变更概要/详情展开），支持按类型（全部/创建/修改/删除/切换）和时间范围（全部/7天/30天）筛选；详情行展示操作前后快照。

### 5.3 任务执行流程

**导入**：出队 → 状态 running → WorkbookReader 逐行读取 → value-converter 校验转换（累计错误行，首批错误即中断——严格模式）→ 全部行组装后在**单事务**内批量写入（含关联全量替换）→ 附件子任务（并发 30）→ commit → 状态 succeeded，写 result/progress；任何失败或 cancel → rollback → failed/canceled。进度按批次更新 progressCurrent（DB 落盘供轮询）。

**导出**：出队 → running → 游标分页查询（合并权限 filter）→ WorkbookWriter 流式写 xlsx（关联表 Sheet/独立文件、日期格式化、关联值格式化、超百万行分表）→ 需要时打包 tar.gz（含附件）→ succeeded 写 filePath/fileSize。

**启动恢复**：应用启动完成后（`afterStart`/`afterSync` 钩子；`load()` 阶段 DB 未 sync，严禁查库）将 `pending/running` 残留任务标记为 `failed`（message="服务重启中断"）。

### 5.4 文件存储

- 目录：`storage/sjgl02/`（导入源文件 `imports/`、导出结果 `exports/`、临时文件 `tmp/`、错误报告 `reports/`）；
- 临时上传文件 30 分钟清理；导出结果文件随任务永久保留（任务不删除）。
