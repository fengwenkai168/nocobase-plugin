# 导出功能

## 1. 功能概述

支持将 NocoBase 数据表数据导出为 Excel (.xlsx) 文件，核心能力：

- **单表导出**：指定一张数据表，导出全部或所选字段
- **全表导出（`__all__`）**：一次导出系统中所有可访问的数据表
- **关联表导出**：将关联数据以展平列或子 Sheet 形式导出
- **百万级支持**：基于游标分页 + 子进程流式写入，单表支持百万行
- **权限隔离**：表级可见性 + 字段级控制，用户仅可导出有权导出的数据

## 2. 用户使用流程

### 2.1 单表导出（标准流程）

1. 用户进入"数据管理"→"导出"面板
2. 系统根据当前用户的表级权限，展示可导出的数据表列表
   - 无 `allowExport=true` 权限的表不下拉不可见
3. 用户选择一张表后，系统根据字段级权限加载可导出字段列表
   - 无权限的字段在勾选列表中不显示（或以灰色禁用态显示）
   - 鼠标悬浮提示："当前用户无权导出该字段"
4. 用户勾选所需字段，配置过滤条件（可选），选择是否包含关联表
5. 点击"开始导出"→ 系统创建导出任务（status = pending）
6. 自动跳转到任务面板，实时查看进度条
7. 导出完成后，"下载"按钮变为可点击
8. 用户点击下载 → 浏览器保存 `.xlsx` 文件

### 2.2 全表导出（管理员流程）

1. 管理员在表选择下拉中选择"全部数据表"
2. 指定一个权限来源角色（permSource），系统按该角色的权限导出各表
3. 确认 → 系统遍历所有表，为每张表创建独立 Sheet
4. 后续同单表导出的任务监控 + 下载流程

### 2.3 取消导出

- 导出执行中，用户可在任务面板点击"取消"
- Worker 收到取消信号 → 清理临时文件 → 退出

## 3. 核心流程（系统视角）

```
用户选择配置 → 创建任务(DB) → Worker 子进程执行 → 下载文件
```

```
┌──────────┐   ┌──────────┐   ┌──────────────┐   ┌──────────┐
│ 配置导出  │ → │ 创建任务  │ → │ Worker 执行   │ → │ 下载文件  │
│ 选择表/   │   │ status=   │   │ 游标分页读取  │   │ GET /    │
│ 字段/条件 │   │ pending   │   │ 流式写入Excel│   │ download │
└──────────┘   └──────────┘   └──────────────┘   └──────────┘
```

## 4. 架构设计

### 4.1 进程隔离

导出在独立子进程中执行，避免长时间占用主进程事件循环：

```
主进程                               子进程 (export-worker.ts)
  │                                      │
  │── fork('export-worker.js') ──────→   │
  │                                      │
  │  ←── { type: 'progress', pct } ────  │  进度上报
  │  ←── { type: 'done', path } ────────  │  完成通知
  │  ←── { type: 'error', msg } ────────  │  错误通知
  │                                      │
  │── { type: 'cancel' } ────────────→   │  取消信号
```

### 4.2 串行队列 + 僵尸守卫

- 同一时间只有一个导出 Worker 运行
- `zombie-guard.ts` 定期扫描（30s 间隔）：
  - 检测已退出但状态未更新的 Worker
  - 恢复卡死任务为 `failed`
  - 清理超过 24h 的过期任务

### 4.3 流式写入

使用 `exceljs` 的 `stream.xlsx.WorkbookWriter`，逐批写入不加载全部数据到内存：

```
游标分页读取 (每批 500 条) → 逐批写入 ExcelJS stream → flush → 保存文件
```

内存消耗稳定在 ~50MB 以内。

## 5. 导出模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **单表导出** | 选择一张表 + 特定字段 + 过滤条件 | 日常数据导出 |
| **全表导出（`__all__`）** | 遍历所有表，每张表独立 Sheet | 全量备份/迁移 |
| **关联表导出** | 主表导出时附带关联子表 | 含关联关系的业务数据导出 |

## 6. 子进程调度系统

### 6.1 调度器原理

`zombie-guard.ts` 中的 `runSchedule()`：

1. 从 DB 查询 `status = 'pending'` 且 `type = 'export'` 的任务
2. 选择最早创建的一条
3. fork `export-worker.ts`，传入任务参数（表名、字段、条件、存储路径）
4. 监听子进程心跳（每 5s），超时 60s 无响应标记为 failed

### 6.2 Worker 生命周期

```
created (pending) → processing → completed / failed
                                → cancelled (用户主动取消)
```

### 6.3 心跳与超时

- Worker 每隔 5s 发送 `{ type: 'heartbeat' }`
- 主进程 60s 未收到心跳 → 标记任务 failed → SIGKILL

### 6.4 Crash 自动恢复

Worker crash 时：
1. 主进程 `exit` 事件触发
2. 检查任务是否仍在 processing
3. 是 → 自动重新排队或标记 failed
4. 调度器 30s 后重试

## 7. 百万级导出引擎

### 7.1 游标分页

```
cursor = 0
batchSize = 500
while true:
    rows = repo.find({ offset: cursor, limit: batchSize })
    if rows.length === 0: break
    worksheet.addRows(rows)
    cursor += batchSize
    sendProgress(cursor / total * 100)
```

### 7.2 合并扫描

关联表导出分两阶段：
1. **阶段一**：扫描主表数据，提取关联外键值集合
2. **阶段二**：使用 `WHERE fk IN (集合)` 批量读取关联数据

### 7.3 Excel 流式写入

```typescript
const workbook = new Excel.stream.xlsx.WorkbookWriter({
  stream: fs.createWriteStream(path)
});
const worksheet = workbook.addWorksheet('Sheet1');
for (const row of batch) {
    worksheet.addRow(row).commit();
}
workbook.commit();
```

## 8. 关联表导出

### 8.1 展平模式

belongsTo / hasOne 关联：将关联字段展平到主表同一行中，列名格式 `{关联名}.{字段名}`。

### 8.2 子 Sheet 模式

hasMany 关联：在同一个文件中另起一个 Sheet，命名规则 `{主表名}.{关联名}`。

## 9. 样式与格式

- **表头行**：加粗、背景色 #4472C4、白色字体
- **列宽**：自动适配（最长 50 字符）
- **日期字段**：格式 `YYYY-MM-DD HH:mm:ss`
- **附件字段**：导出为 URL 列表，以 `; ` 分隔
- **文件名**：`{表中文名}_{YYYYMMDD_HHmmss}.xlsx`

## 10. API 接口

| 端点 | 方法 | 说明 |
|------|------|------|
| `export:create` | POST | 创建导出任务 |
| `export:preview` | GET | 预览导出数据量 |
| `export:download` | GET | 下载已完成的导出文件 |
| `export:cancel` | POST | 取消正在执行的导出 |

### 创建导出任务

```typescript
POST /api/sjgl02/export:create
{
  tableName: string,             // 表名 / '__all__'
  fields?: string[],              // 选中字段（空=全部）
  filter?: FilterParams,          // 过滤条件
  includeAssociations?: boolean,  // 是否包含关联表
  fileName?: string,              // 自定义文件名
  permSource?: string             // 权限来源（__all__ 模式必传）
}
```

### 下载文件

```typescript
GET /api/sjgl02/export:download?taskId={taskId}
```

响应：`Content-Disposition: attachment; filename="xxx.xlsx"`

## 11. 权限控制（用户视角）

### 11.1 表级可见性

用户在导出面板中看到的"数据表"下拉选项：

| 用户身份 | 看到的结果 |
|----------|-----------|
| admin / root | 全部数据表 |
| 普通用户（有表权限） | 仅显示 `allowExport=true` 的表 |
| 普通用户（无权限） | 下拉列表为空，提示"无可用数据表" |

### 11.2 字段级控制

选择表后，"导出字段"勾选框列表根据字段级权限过滤：

| 字段权限状态 | UI 表现 |
|-------------|---------|
| 在 `exportableFields` 中 | 正常显示复选框 |
| 不在 `exportableFields` 中 | 不显示 / 灰色禁用 + title 提示"无权导出" |

底层规则由 `PermissionService.getTablePermissions()` 返回的 `exportableFields` 数组决定。

### 11.3 权限来源（permSource）

`__all__` 模式需额外指定 permSource（角色标识），导出时权限判断以该角色为准。

### 11.4 安全边界（已知问题）

- `downloadExport` 接口目前无独立鉴权——知道 taskId 即可下载文件
- 导出创建路由依赖 `isAdminOrRoot` 检查，但部分内部路径可绕过

## 12. 配置项

| 配置 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| batchSize | number | 500 | 每批读取行数 |
| maxFileSize | number | 500MB | 单文件上限 |
| workerTimeout | number | 3600000 | Worker 超时 (1h) |
| tempDir | string | storage/tmp/ | 临时文件存储目录 |

## 13. 关键技术点

### 13.1 大文件处理

超过 100MB 的导出文件自动分片，打包为 ZIP 下载。

### 13.2 取消机制

取消信号通过 DB 状态 + 内存标志双重传递：
1. 用户调用 cancel API → DB 任务状态更新为 `cancelled`
2. Worker 每隔 5s 检查 DB 状态
3. 发现 `cancelled` → 清理临时文件后退出

### 13.3 文件名编码

`encodeURIComponent(fileName)` 确保中文文件名跨浏览器兼容。

## 14. 导出限制

| 限制项 | 说明 |
|--------|------|
| 单表最大行数 | 推荐 ≤ 500 万行 |
| 关联层级深度 | 最多 2 层展平，更深 → 子 Sheet |
| 文件大小限制 | 单文件 ≤ 500MB |
| 并发导出 | 串行队列，同一时间仅一个导出任务 |
