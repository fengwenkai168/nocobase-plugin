# 任务管理

## 1. 功能概述

所有导入和导出任务共用统一的"任务"生命周期管理体系，核心能力：

- **统一任务模型**：导入/导出共用同一个 `sjgl02_tasks` 表
- **完整状态机**：pending → processing → completed / failed / cancelled
- **取消机制**：DB 状态 + 内存标志双重检测，支持任务级取消
- **执行日志**：导入/导出执行过程的详细日志记录与查看
- **查看范围控制**：普通用户仅看自己的任务，管理员可看全部

## 2. 用户使用流程

### 2.1 查看任务列表

1. 用户进入"数据管理"→"任务"面板
2. 系统根据用户身份返回任务列表：
   - 管理员：全部任务（分页，按创建时间倒序）
   - 普通用户：仅本人创建的任务（`createdById = 当前用户`）
3. 列表中展示任务概要：类型（导入/导出）、目标表、状态、进度、创建时间

### 2.2 查看任务详情

1. 点击某条任务 → 进入任务详情页
2. 详情包含：
   - 基本信息：任务类型、目标表、导入/导出模式、创建人、创建时间
   - 执行配置：选择的字段、过滤条件、关联表配置
   - 进度展示：进度百分比 + 当前阶段描述
   - 状态标签：pending（灰色）/ processing（蓝色）/ completed（绿色）/ failed（红色）/ cancelled（黄色）

### 2.3 查看执行日志

1. 在任务详情页下方展开"执行日志"区域
2. 日志按时间线展示，每条包含：
   - 时间戳
   - 日志级别（info / warn / error）
   - 日志内容
3. 支持自动滚动到最新日志

### 2.4 取消任务

1. 任务状态为 processing 时，详情页显示"取消"按钮
2. 点击 → 确认对话框 → 确认后发送 cancel 请求
3. 任务状态变为 cancelled，正在执行的 Worker 收到信号后清理退出
4. 导入任务已写入影子表的数据自动回滚

## 4. 状态机

```
                  ┌──→ completed
pending → processing ──→ failed
                  └──→ cancelled
```

| 状态 | 说明 | 可执行操作 |
|------|------|-----------|
| pending | 已创建，等待调度 | 取消 |
| processing | 正在执行 | 取消、查看日志 |
| completed | 执行成功 | 下载（导出）、查看详情 |
| failed | 执行失败 | 查看错误、重试 |
| cancelled | 用户主动取消 | 查看详情 |

## 5. 任务生命周期

### 5.1 创建（pending）

导入/导出 action 创建任务记录，status = `pending`，写入 `sjgl02_tasks` 表。

### 5.2 执行（processing）

- **导入**：由请求内逻辑直接执行，逐阶段推进
- **导出**：由 `zombie-guard` 调度器 fork Worker 子进程执行

执行过程中定期更新 `progress`、`stage`、`processedRows` 字段。

### 5.3 完成（completed）

- 导入：影子表迁移完成 → status = `completed`
- 导出：Worker 发回 done 信号 → status = `completed`

### 5.4 失败（failed）

- 导入：任意阶段抛出异常 → 自动回滚 → status = `failed`
- 导出：Worker crash / 超时 → status = `failed`

### 5.5 取消（cancelled）

用户手动取消 → status = `cancelled`

## 6. 取消机制

### 6.1 双重检测

```
主动（API 层）:
  cancel API → DB UPDATE status='cancelled' WHERE id=taskId

被动（执行层）:
  每批次写入前检查 cancelFlags.has(taskId)  // 内存 Set
  或从 DB 读取最新状态
```

### 6.2 取消后的行为

- **导入**：当前批次完成后停止，自动回滚影子表
- **导出**：Worker 收到取消信号 → 删除临时文件 → 进程退出

### 6.3 取消限制

- 仅 processing 状态的任务可取消
- completed / failed 状态的任务不可取消

## 7. 查看范围控制

| 接口 | 管理员 | 普通用户 |
|------|--------|----------|
| 任务列表 | 全部任务 | `createdById = 当前用户` |
| 任务详情 | 任意任务 | 仅自己的任务 |
| 执行日志 | 任意任务的日志 | 仅自己任务的日志 |

底层通过 `permission-check.ts` 的 `isAdminOrRoot(ctx)` 判断用户身份。

## 8. 执行日志

### 8.1 写入时机

导入导出各阶段写入关键日志：
- 任务创建
- 阶段切换（上传完成/开始解析/开始迁移）
- 每批处理完成（可选，频率可配置）
- 异常/错误发生
- 任务完成/失败/取消

### 8.2 日志分页

```typescript
GET /api/sjgl02/taskLogs:list?taskId={taskId}&page=1&pageSize=50
```

返回按 `createdAt ASC` 排序的分页日志。

## 9. API 接口

| 端点 | 方法 | 说明 |
|------|------|------|
| `tasks:list` | GET | 任务列表（分页，含查看范围过滤） |
| `tasks:get` | GET | 任务详情 |
| `tasks:cancel` | POST | 取消任务 |
| `taskLogs:list` | GET | 任务执行日志（分页） |


## 10. 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 任务一直 pending | 导出任务排队中，前面有任务未完成 | 等待或取消前面任务 |
| 任务状态为 processing 但无进度更新 | Worker 可能已 crash | 等待系统自动恢复或联系管理员 |
| 取消任务后仍在执行 | 取消信号因 Worker 卡死未收到 | 系统会在超时后强制标记 failed |
| 看不到别人创建的任务 | 普通用户查看范围仅限于自己 | 联系管理员查看 |
| 日志不全 | 可能日志写入频率低或 Worker 突然退出 | 根据 `stage` 字段大致判断执行进度 |
