# 导入功能

## 1. 功能概述

支持将 Excel (.xlsx/.xls) 文件数据导入到 NocoBase 数据表中，核心能力：

- **多模式导入**：Insert（新增）、Update（更新）、Upsert（新增+更新）
- **四阶段流水线**：上传 → 解析 → 执行 → 影子表迁移，每阶段可独立重试
- **百万级支持**：流式解析 + 批量提交 + 影子表机制，单表支持百万行导入
- **智能匹配**：自动按表头名称匹配字段，支持自定义列映射
- **错误回滚**：导入失败自动回滚，不污染线上数据

## 2. 用户使用流程

### 2.1 标准导入流程

1. 用户进入"数据管理"→"导入"面板
2. 选择目标数据表（下拉列表根据表级导入权限过滤，无权表不可见）
3. 选择导入模式：新增 / 更新 / 新增+更新
4. 上传 Excel 文件（支持 .xlsx/.xls）
5. 系统自动解析文件，识别表头、行数、Sheet 列表
6. 进入列映射步骤：
   - 系统按表头名称自动匹配字段（支持模糊匹配）
   - 用户可手动调整字段映射关系
   - 标记关键字段（唯一键、必填校验）
7. 进入预览步骤：
   - 系统展示前 20 行数据样例
   - 标红显示校验失败的行/列（如必填字段为空、类型不匹配）
8. 用户确认无误后点击"执行导入"
9. 系统显示导入进度（当前阶段：解析中/写入影子表/合并中）
10. 完成或失败均有详细结果报告（成功行数、失败行数、错误详情）

### 2.2 取消流程

- 导入执行过程中，用户可随时点击"取消"
- 系统标记任务为 cancelled，当前批次完成后停止
- 已写入影子表的数据自动回滚

## 3. 四阶段流程

```
Stage 1: uploadParse → Stage 2: executeImport → Stage 3: migrateToRealTable
                         ↕ (可取消)
                    Stage 2.5: rollback (失败时)
```

### Stage 1 — 上传与解析

| 步骤 | 说明 |
|------|------|
| 接收文件 | POST multipart/form-data |
| 格式检测 | 校验扩展名、MIME type |
| Sheet 选择 | 默认第一个，支持切换 |
| 表头识别 | 第一行作为列名，支持指定 headerRow |
| 类型推导 | 按列内容推断字段类型（string/number/date） |
| 数据行读取 | 流式读取，不加载全部到内存 |

### Stage 2 — 执行导入

| 步骤 | 说明 |
|------|------|
| 字段映射 | 按表头匹配，自动 + 手动 |
| 数据校验 | 必填字段、唯一约束、类型校验 |
| 影子表写入 | 先写入影子表，不直接影响主表 |
| 进度上报 | 每批完成百分比 |

### Stage 3 — 影子表→主表迁移

| 步骤 | 说明 |
|------|------|
| 锁表 | 获取表级锁防止并发冲突 |
| Insert 模式 | INSERT INTO ... SELECT FROM 影子表 |
| Update 模式 | UPDATE ... JOIN 影子表 WHERE 唯一键匹配 |
| Upsert 模式 | INSERT ON CONFLICT DO UPDATE |
| 清理 | 迁移成功后删除影子表 |

### Rollback — 回滚

- 任何阶段失败时，自动删除影子表
- 如果迁移阶段失败，记录失败但不清除影子表（支持手动恢复）

## 4. 三种导入模式

| 模式 | 行为 | 适用场景 |
|------|------|----------|
| **Insert** | 全部新增，遇到唯一冲突报错 | 全新数据导入 |
| **Update** | 按唯一键匹配更新已有行，不匹配则跳过 | 批量更新已有数据 |
| **Upsert** | 匹配则更新，不匹配则新增 | 同步/合并数据 |

唯一键由用户在上传后手动指定，默认为表的主键。

## 5. 架构设计

### 5.1 请求内执行（非进程分离）

导入在主进程请求内执行，通过流式 + 批量提交避免阻塞：

```
Client → 上传 → 解析(内存流) → 影子表写入(批量500条) → 迁移 → 响应
```

### 5.2 影子表机制

```
主表: target_table
影子表: _import_{taskId}_{tableName}

创建影子表时复制主表结构（不含约束触发器）：
  CREATE TABLE _import_xxx LIKE target_table (INCLUDING INDEXES)

迁移时：
  INSERT INTO target_table SELECT * FROM _import_xxx
```

优点：
- 导入失败不影响主表数据
- 迁移是单条 SQL，性能最优
- 支持并发读（影子表写入不影响主表读）

### 5.3 批量提交

每 500 条作为一个事务批次提交到影子表，控制内存占用：

```
批次 1: INSERT INTO 影子表 (rows 1-500)
批次 2: INSERT INTO 影子表 (rows 501-1000)
...
最终迁移: INSERT INTO 主表 SELECT * FROM 影子表
```

### 5.4 取消机制

- 内存取消标志 `cancelFlags: Set<taskId>`
- 每批次写入前检查标志
- 发现取消 → 停止后续批次 → 自动触发回滚

## 6. 数据解析引擎

### 6.1 文件格式支持

| 格式 | 引擎 | 说明 |
|------|------|------|
| .xlsx | exceljs | 流式读取，支持大文件 |
| .xls | exceljs | 兼容旧格式 |

### 6.2 列映射

自动匹配策略（按优先级）：
1. 表头中文名 → 字段中文名（displayName）
2. 表头英文名 → 字段名（name）
3. 模糊匹配（移除空格、特殊字符后比对）
4. 人工拖拽映射（兜底）

### 6.3 类型推导与转换

| Excel 值类型 | 目标字段类型 | 转换逻辑 |
|-------------|-------------|----------|
| 字符串 | string | 直接写入 |
| 数字 | integer/float | parseFloat |
| 日期序列号 | date | Excel 序列号 → JS Date |
| 日期字符串 | date | 尝试多种格式解析 |
| 布尔值 | boolean | true/false/1/0 推导 |
| 空单元格 | 任意 | 写入 NULL（可配置默认值） |

### 6.4 附件字段处理

Excel 列为 URL 列表（以分号分隔），导入时下载文件并创建附件记录。

## 7. 百万级优化策略

| 策略 | 说明 |
|------|------|
| 流式解析 | 使用 exceljs stream 模式，不加载全文到内存 |
| 批量提交 | 每 500 条一批，控制事务大小 |
| 影子表免索引 | 影子表去除外键/唯一约束，写入更快 |
| 迁移 SQL 优化 | 使用 INSERT SELECT 而非逐条 INSERT |
| 游标读取 | 读取主表已有数据时分页处理，不一次性加载 |
| 内存控制 | 解析 + 写入全程峰值 < 100MB |

## 8. API 接口

| 端点 | 方法 | 说明 |
|------|------|------|
| `import:uploadParse` | POST | 上传文件 + 解析，返回列映射和预览 |
| `import:execute` | POST | 执行导入（Stage 2 + Stage 3） |
| `import:cancel` | POST | 取消正在执行的导入 |
| `import:rollback` | POST | 手动回滚已完成的导入 |
| `import:getMapping` | GET | 获取字段映射配置 |
| `import:switchSheet` | POST | 切换 Sheet 重新解析 |

### uploadParse

```typescript
POST /api/sjgl02/import:uploadParse
Body: FormData { file: File, tableName: string, headerRow?: number }
Response: {
  sheets: string[],
  totalRows: number,
  columns: { label: string, type: string }[],
  preview: Row[]  // 前20行
}
```

### execute

```typescript
POST /api/sjgl02/import:execute
Body: {
  taskId: number,
  mode: 'insert' | 'update' | 'upsert',
  mapping: { excelColumn: string, fieldName: string }[],
  uniqueKey?: string,
  skipRows?: number
}
Response: { success: number, failed: number, errors: { row: number, msg: string }[] }
```

## 9. 权限控制（用户视角）

### 9.1 表级可见性

用户在导入面板中看到的"目标数据表"下拉选项受表级权限控制：

| 用户身份 | 看到的结果 |
|----------|-----------|
| admin / root | 全部数据表 |
| 普通用户（有表权限） | 仅显示 `allowImport=true` 的表 |
| 普通用户（无权限） | 下拉列表为空，提示"无可用数据表" |

### 9.2 导入模式限制

`sjgl02_table_permissions` 中的 `importModes` 字段定义该表允许使用的导入模式：

| 配置值 | UI 表现 |
|--------|---------|
| `['insert']` | 模式选择下拉仅显示"新增" |
| `['insert', 'update']` | 显示"新增"和"更新" |
| `['upsert']` | 仅显示"新增+更新" |
| 空/未配置 | 默认全部模式可用 |

### 9.3 字段级限制

导入时用户无法为目标表中无权写入的字段指定映射。

### 9.4 权限来源（permSource）

跨角色导入时通过 `permSource` 参数指定权限来源，权限判断以该角色为准而非当前用户。

### 9.5 安全边界（已知问题）

- `import:uploadParse` 依赖请求内 `ctx.state.currentUser` 鉴权
- 部分内部调用路径（如重试）不经过标准鉴权中间件

## 10. 配置项

| 配置 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| batchSize | number | 500 | 每批写入行数 |
| maxFileSize | number | 100MB | 单文件大小上限 |
| headerRow | number | 1 | 表头所在行号 |
| maxColumns | number | 200 | 最大列数限制 |
| allowedMimeTypes | string[] | xlsx/xls | 允许的文件 MIME 类型 |

## 11. 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 上传失败：文件过大 | 超过 maxFileSize | 增大配置或拆分文件 |
| 列无法匹配 | 表头名与字段名差异太大 | 手动拖拽映射 |
| 导入慢 | 每批行数太小或表有大量约束 | 增大 batchSize，临时禁用触发器 |
| 必填字段校验失败 | Excel 中必填列为空 | 补填数据后重试 |
| 唯一键冲突（Insert 模式） | 数据已存在 | 切换为 Upsert 模式 |
