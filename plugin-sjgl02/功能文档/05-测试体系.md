# 测试体系

## 1. 测试策略

采用三层测试金字塔，覆盖百万级导入导出的功能正确性、权限安全性和性能基准：

```
     ┌──────┐
     │ E2E  │  ← 真实浏览器 + 真实 NocoBase 服务 + 真实数据库
     │  35+ │     覆盖完整业务流程
    ┌┴──────┴┐
    │ 客户端  │  ← React Testing Library + hooks 测试
    │  12+   │     覆盖前端组件逻辑、状态管理、权限 UI 表现
   ┌┴────────┴┐
   │  服务端   │  ← 模拟 NocoBase 运行时 + PostgreSQL
   │   27+    │     覆盖导入/导出/权限/任务全部核心逻辑
   └──────────┘
```

## 5. 运行脚本

```bash
# 全部测试
yarn test

# 分层运行
yarn test:server       # 服务端单元测试（27+）
yarn test:client       # 客户端单元测试（12+）
yarn test:e2e          # E2E 测试（35+）

# 性能测试
yarn test:e2e --grep "perf"
```

## 6. 测试覆盖说明

### 已覆盖

- 导入：三种模式、文件解析、列映射、校验、影子表迁移、回滚、取消
- 导出：单表/全表/关联导出、子进程、样式、字段过滤
- 任务：状态流转、查看范围、取消、日志
- 权限：角色级/用户级 CRUD、查询合并、审计日志
- 安全：角色切换、用户覆盖、越权拒绝
- 性能：10 万/50 万行基准

### 未覆盖（待补充）

| 领域 | 缺少的测试 |
|------|-----------|
| Worker 心跳超时恢复 | 模拟 Worker 卡死后的自动恢复流程 |
| 并发取消 race condition | 多个取消请求同时到达 |
| 影子表迁移中断恢复 | 迁移阶段服务重启后的处理 |
| 500 万+ 行性能基线 | 目前仅到 50 万行 |
| Worker crash 后自动重试 | crash 后调度器重新排队的完整链路 |
| 导出文件路径穿越攻击 | 恶意 fileName 包含 `../` 的场景 |
